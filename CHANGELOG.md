# Changelog

All notable user-visible changes to Practise360 are recorded here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).

Add entries under **Unreleased** in the same PR as the change, grouped as Added / Changed / Fixed / Removed / Security. Move them under a version heading when releasing.

## [Unreleased]

### Added
- **Audit log** (`/audit-log`, Super Admin only, in the sidebar): every change and sign-in across Practise360 — roles granted and revoked, roles edited, practices, groups, members, invitations, contributions, certifications, usage reports, and password / Google / invitation sign-ins — including attempts that were refused or failed, with the error shown. Each row shows when, who, what (with people, practices, groups, roles, contributions and certifications by name), the outcome, and the IP address. Filter by text, area, outcome, person and date range; 50 per page, newest first. Passwords, tokens and file contents are never recorded, and entries can't be edited or deleted. New permission `platform.audit.view` — run `npm run sync-roles -w api` on existing databases. API: `GET /audit-log`, documented in Swagger.

### Changed
- The **AI Tracker** sidebar entry is now **Claude Usage Report — Coming soon**, greyed out and not clickable. Its Home tile matches (Coming soon, not a link).

### Security
- **Google-only accounts**: accounts created by Google sign-in, and the real people set up on the demo deployment, can't be opened with the shared dev password and don't appear in the login page's demo user list.
- New `npm run reset -w api` script empties a database (after writing a full JSON backup) and starts it over with only the RBAC catalog and the Super Admins given on the command line.

### Added
- **Add several people by email at once**: Add member on a practice and on a group (for Practice Managers and Practices Admin) has a new **Add by email** tab. Type addresses separated by commas — each turns into a chip with an × to remove it (Enter, leaving the field or pasting a list works too; Backspace removes the last one; invalid addresses show in red and repeats are ignored). Submitting handles each address: people already on Practise360 are added straight away, everyone else is emailed an invitation, and anyone already in the practice is left as they are. A summary toast appears, or a per-address list (with join links when email isn't set up) if anything needs attention. API: `POST /practices/:id/invites/bulk` (up to 50 addresses, same checks per address as a single invite), documented in Swagger. UI kit: new `EmailChipsInput` / `EmailChip`.
- **Add a contribution for someone else**: Practice Leads (for their own group's members), Practice Managers (anyone in their practice) and Practices Admin can pick an **Owner** on *Start a contribution* to add it on a member's behalf. The member owns it and submits it as usual. It's marked **"Added by …"** on the contributions list, on the contribution's page and in its timeline, and whoever added it can't review or approve it. API: optional `ownerId` on `POST /contributions`, `GET /contributions/practices/:id/owners`, and `addedBy` / `canAddForIn` in responses.
- **Sign in with Google**: "Continue with Google" on the sign-in page now works. Signing in with Google for the first time creates your Practise360 account. It starts with no access: the home page explains that you're not part of a practice yet and to ask your Practice Manager to add you. Configured with `GOOGLE_CLIENT_ID` (and optionally `GOOGLE_ALLOWED_DOMAINS`) on the API — see `docs/runbooks/deployment.md`. The username/password form now only appears in dev mode.
- **Group pages** (`/practices/:id/groups/:groupId`): open a group from its card ("Open group") on a practice's Groups & members tab. The page shows the group's Lead and the Practice Manager, then three tabs: **Overview** (the group's own Markdown text and shared files), **Members** (who's in the group, with their roles) and **Contributions** (work started by the group's members). Groups don't have sub-groups.
- **Group Leads run their group**: the group's Lead — as well as the Practice Manager and Practices Admin — edits the group's Overview and files, adds practice members who aren't in a group yet, and removes members from it (they stay in the practice). Managers and Practices Admin can also move people in from other groups, or add and invite people from outside the practice, from the same Add member dialog. Renaming or deleting a group and choosing its Lead stay with the Manager and Practices Admin. New permission `practices.group.update` (Practice Lead, Practice Manager, Practices Admin) — run `npm run sync-roles -w api` on existing databases.
- **Contributions tab** on every practice page and group page: the same list as Practices → Contributions (All / Mine / Awaiting my review, filters, table), limited to that practice or group.
- **Start a contribution** is now a button at the top of every practice and group page, whatever tab is open, for anyone who can contribute in that practice. The form opens with the practice already picked and returns to that page's Contributions tab afterwards.
- API: `GET/PUT /practices/:id/groups/:groupId/overview` and its `/files` routes; `GET /contributions?groupId=`; group `actions` now include `update` and `manageMembers`. Documented in Swagger.
- **Invite people by email**: in every person picker on the Practices pages — choosing a practice's Manager (also when creating a practice), choosing or creating a group's Lead, and Add member — type an email. If nobody on Practise360 has it, pick "Invite <email>": they get a NULogic-branded email with a **Join Practise360** button, and when they join (`/invite/…`, they just confirm their name) they're signed in and become the Manager, the group's Lead, or a member (optionally in a group). Invitations need the same rights as the direct appointment. Open invitations are listed under **Pending invitations** on the Groups & members tab, with Resend and Cancel; the Manager card and group cards show who's invited. Links work once and expire after 7 days.
- Sign in with your **email** as well as your username (dev login: password `password` for everyone). Pickers and Access control search by email too.
- API: `POST /practices/:id/invites`, `DELETE /practices/:id/invites/:inviteId`, `POST /practices/:id/invites/:inviteId/resend`, and public `GET /invites/:token` + `POST /invites/:token/accept`, documented in Swagger. New env vars `SMTP_URL`, `MAIL_FROM`, `WEB_URL`, `INVITE_EMAIL_DOMAINS` (see `docs/runbooks/deployment.md`). The dev seed gives every user a synthetic `<username>@example.com` email.
- **People profiles** (`/people/:id`): click any person's name — the Practices Admin on `/practices`, Managers, Leads, members, contribution owners and reviewers, certification owners, timeline authors, AI Tracker team reports, Access control — to open their profile: practices, group and roles, contributions, certifications and Claude usage reports, plus highlights of published work and certifications earned. You only see what your access already shows elsewhere (e.g. practitioners still don't see each other's certifications). "My profile" is in the account menu.
- API: `GET /people/:id`, documented in Swagger.
- **Practice Overview** (`/practices/:id`, now the first tab on a practice page, next to "Groups & members"): key information about the practice in Markdown — what it does, ways of working, key links, who to ask — plus shared files (guides, templates, decks; up to 4 MB each). Everyone in the practice reads it and opens the files; the Practice Manager and Practices Admin edit it and upload or remove files.
- The Practices page names the **Practices Admin** under its title.
- **Show stats / Hide stats** toggle on pages with count tiles (Practices, a practice page, Contributions, Certification Tracker, Access control, AI Tracker → Team reports). Tiles start hidden; the choice is remembered and applies on every page.
- API: `GET/PUT /practices/:id/overview` and `/practices/:id/overview/files` (upload, download, remove); `GET /practices` also returns `admins`. Documented in Swagger.
- **Practices and groups** (`/practices`, now the Practices landing page): every practice shows its Manager and its **groups** (e.g. Digital Engineering → Fullstack, DevOps, Mobile App; Platform → Commercetools, Magento), each with its own **Practice Lead** and members. Practices Admin creates practices and chooses each one's Manager; the Manager (or Practices Admin) creates, renames and deletes groups, chooses each group's Lead, adds people to the practice and moves them between groups. One Manager per practice and one Lead per group — choosing a new one replaces the current one after a confirmation. Everyone in a practice sees its structure read-only.
- New permission `practices.group.manage` (Practice Manager, Practices Admin) and a new `group` scope under each practice (see `docs/rbac.md` §4 "Practices and groups"). Run `npm run sync-roles -w api` on existing databases.
- API: `/practices` routes (list, create, rename, Manager, members, groups, group Lead), documented in Swagger.
- **Certification Tracker** (`/certifications`, "Certifications" in the sidebar): practice members plan certifications and courses with start and due dates, then submit a completion — certificate (PDF or image), verification link (required), optional credential ID and expiry date, and an optional reimbursement claim (amount in INR or USD plus the receipt). Completions go through the same two-step approval as contributions: Practice Lead (approve, ask for clarification, or reject — which reopens the plan), then Practice Manager, whose approval marks it Completed and approves the reimbursement. Leads, Managers and Practices Admin can **recommend** (the member accepts with their own dates or declines) or **assign** (mandatory, with a due date) a certification to one or more members, from the shared catalog or as a new entry that's added to it. Tabs: My plans, Team, Awaiting my review and Catalog (Cert Admin can edit or retire entries); every change and decision is logged on the plan's timeline. Overdue and expired certifications are flagged.
- New permissions `cert.plan.review` (Lead step) and `cert.catalog.create` (add to the catalog); `cert.plan.verify` is now the Manager step (see `docs/rbac.md`). Run `npm run sync-roles -w api` on existing databases.
- API: `/certifications` routes (catalog, plans, assignments, files, submit, review), documented in Swagger. The dev seed adds a starter catalog.
- Practices → **Contributions** (`/practices`): start a contribution (Reusable framework / accelerator, Automation / internal tool, Client win story, Internal case study, Blog, or a custom type) with a Markdown description — or import a Word `.docx` / `.md` and keep its formatting. Invite practice members or ask to join, post progress updates with attachments, then submit (summary, impact, documents; repo/demo/other links optional) for a two-step review: Practice Lead (approve, decline or ask for clarification), then Practice Manager, whose approval publishes it. Every step is logged on the contribution's timeline. Leads and Managers get an "Awaiting my review" queue plus filters by practice, status, type, owner and overdue.
- New permissions `practices.contribution.view/create/update:own/manage/review/approve` (see `docs/rbac.md`); Practices appears in the sidebar for practice members.
- API: `/contributions` routes, documented in Swagger.
- Super Admin can edit system roles (name, description, permissions) from Access control → Roles, via the new `platform.roles.manage` permission. Super Admin itself stays read-only; `platform.*` permissions are limited to platform roles.
- AI Tracker → Claude usage reports (`/ai-tracker`): download the `claude-usage-report` Claude skill, generate a NULogic-branded monthly PDF from your Claude history, and upload it (one per month, re-upload replaces). Managers get a Team reports tab with Submitted/Pending status per person and month.
- In-app PDF viewer: page navigation, page-number jump, zoom with fit-to-width, download, keyboard shortcuts (←/→, Esc).
- API: `/ai/usage-reports` routes (own upload/list/delete, team view, PDF download), documented in Swagger; `npm run sync-roles -w api` to apply catalog changes without reseeding.
- API docs: Swagger UI at `/docs` and the OpenAPI 3 spec at `/openapi.json` on the API, covering every route (a test fails if a route is undocumented).
- Sign-in page with username + password (dev mode only; every seeded account uses `password`) and a one-click demo-user list. "Continue with Google" is shown but not implemented yet.
- Home page showing the apps your roles give you, plus links to Settings and Access control.
- Settings page with your account, role assignments and effective permissions.
- Access control portal (`/access-control`): grant and revoke roles per user (pickers only offer what the escalation guard allows), create/edit/delete custom practice roles, and a read-only permission matrix.
- MongoDB-backed API: dev login, `/me`, and `/rbac/*` routes with server-side permission checks; seed script `npm run seed -w api`.
- Hello-world monorepo: Next.js web (`apps/web`) and Express API (`apps/api`), deployable to Vercel.
- NULogic-branded UI kit in `apps/web` (Tailwind v4 tokens; Button, Badge/StatusBadge, Card, form fields, Modal, Tabs, Table, StatTile, Progress, Avatar, EmptyState/NoAccess, Toast; AppShell with sidebar, top bar and user menu) with a live gallery at `/ui-kit`.
- UI guidelines (`docs/ui-guidelines.md`) and `ui-builder` project skill.
- Initial RBAC design (`docs/rbac.md`) and mockup generation prompt (`docs/gemini-mockup-prompt.md`).
- Project workflow: `CLAUDE.md`, delivery tracker with Kanban board (`npm run tracker`), QA plan/report folders, review guide and CI.

### Changed
- On a practice page and a group page, "Start a contribution" is the one main (filled) button, so **New group** and **Add member** are now outlined buttons.
- Count tiles at the top of pages are hidden by default (see the Show stats toggle above).
- The Practices page no longer shows the "Each practice has a Manager and is split into groups…" description.
- A practice page opens on its **Overview** tab; groups and members moved to the **Groups & members** tab (`?tab=groups`).
- **Practice Leads now lead a group, not the whole practice.** A Lead reviews contributions and certification completions, and recommends or assigns certifications, only for members of their own group; the Practice Manager still covers everyone (including people not in a group yet). Moving someone to another group hands their open work to that group's Lead. Contributions stay visible to the whole practice.
- Practice contributions moved from `/practices` to `/practices/contributions`, with Overview / Contributions tabs at the top of the Practices app.
- Access control → Grant a role lists practice groups as scopes (Practice Lead is granted there) and refuses a second Manager or Lead with a pointer to the Practices page.
- `npm run sync-roles -w api` keeps system roles' scope level in step with the catalog: it moves Practice Lead to group scope and turns existing practice-wide Lead assignments into Practitioner (it prints who to re-appoint as a group Lead).
- Home page tile for Certification Tracker now opens the app instead of showing "Coming soon". Practice Leads and Managers gain `cert.plan.review` and `cert.catalog.create`; Practices Admin gains `cert.catalog.create`.
- `npm run sync-roles -w api` now also adds brand-new catalog permissions to the system roles whose defaults include them (existing edits are kept).
- Request bodies up to 1 MB are accepted for JSON (long Markdown descriptions).
- Access control → Grant a role: pick the scope first (grouped Platform / Apps / Practices), then a role grantable there — previously role came first and the scope list was hard to read.
- `npm run sync-roles -w api` only inserts missing system roles so Super Admin edits survive; pass `-- --reset` to restore the defaults.
- New permissions `ai.usage.manage:own` (all practice roles, AI Member) and `ai.usage.view` (Practice Manager, Practices Admin, AI Admin) — AI Tracker now appears for every practice member.
- Home page app tile for AI Tracker now opens the app instead of showing "Coming soon".
- Practices Admin now also holds `cert.catalog.view` and all `cert.plan.*` permissions, so it can appoint Practice Managers under the escalation guard (see `docs/rbac.md`).

### Fixed
- An expired or revoked session now sends you back to the sign-in page with "Your session expired. Sign in again to continue." Previously screens stayed open and showed misleading errors (e.g. "You can't start a contribution — you need to be a member of a practice").
- Contributions: text over a field's limit (description 200,000 characters, summary/impact/reply/comment 10,000, progress update 50,000, title 120) is now refused with a message naming the field, instead of being cut off silently. The description and progress editors show a character count near the limit.
- Contributions: impossible dates such as 31 February are refused instead of being saved as a date in March.
- API: a malformed JSON request body returns 400 "Request body isn't valid JSON" instead of a 500 server error.
